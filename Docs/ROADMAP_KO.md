# 구현 순서

현재 단계: 폴더·파일 구성. 아래 기능은 아직 구현 전이다.

| 단계 | 작업 | 확인 기준 |
|---|---|---|
| 1 | Universal 3D 프로젝트 생성, 시작 구성 복사, VS Code 연결 | Console 컴파일 오류 없음 |
| 2 | Game 씬, 바닥·벽·카메라·플레이어 | 맵 전체와 캐릭터 방향이 보임 |
| 3 | Input System 방향키 이동·회전·경계 | 동시 입력으로 대각선 이동, 속도 일정, 멈춰도 방향 유지 |
| 4 | 첫 Web 빌드 | 브라우저에서 클릭 후 이동 가능, 방향키 페이지 스크롤 확인 |
| 5 | Q 발사, 정지한 적, 체력 | Q 길게 누르면 일정 간격 발사, 피해·처치 한 번 처리 |
| 6 | 네 출입구와 적 추적 | 문 바깥 생성→안쪽 진입→추적, 적 수 제한과 접촉 피해 |
| 7 | W 산탄 | 부채꼴 여러 발, Q보다 짧은 사거리, 독립 대기시간 |
| 8 | E 폭탄 | 사용 순간 전방 착탄 지점 확정, 범위 예고·폭발, 중복 피해 방지 |
| 9 | R 범위 공격 | 사용 순간 자신 중심 원형 범위 내 적만 한 번씩 피해 |
| 10 | 하단 HUD | HP·공격력·QWER·남은 대기시간, 일본어 글자 정상 표시 |
| 11 | 진행·점수·아이템 | 시작·일시정지·종료·재도전, 난이도 상승 |
| 12 | 그래픽·사운드·기록·배포 | 웹 로딩·성능·저장·실제 주소 접속 확인 |

각 단계에서 필요한 최소 UI를 먼저 연결하고, 10단계에서 하단 레이아웃을 통일한다.
맵은 우선 중앙 장애물이 없는 방 1개, 적 1종으로 만든다. 장애물이 생기면 경로 탐색을 추가한다.
한 화면 고정 카메라, 바닥 XZ 이동, Y 높이를 기준으로 시작한다.

## QWER 첫 테스트 제안

| 키 | 일본어 이름 | 행동 | 대기시간 |
|---|---|---|---|
| Q | 通常攻撃 | 바라보는 방향 단발 연사 | 스킬 대기시간 0초, 연사 간격 0.25초 |
| W | 散弾 | 전방 단거리 산탄 | 4초 |
| E | 爆弾 | 전방 일정 거리 지점 폭발 | 8초 |
| R | 範囲攻撃 | 자신 중심 원형 범위 공격 | 20초 |

수치는 제안이며 설정 에셋에서 조정한다. 대기시간의 실제 계산·UI 연결은 PlayerCombat/SkillSlotUI 구현 때 진행한다.
W/E/R은 누를 때 한 번 실행하며, 대기 중 연속 발동하지 않는다. 일시정지 중에는 진행 시간을 멈춘다.
사망·재시작 시 적·총알·폭탄·아이템·스킬 타이머를 함께 초기화한다.

## 웹에서 확인할 항목

- 게임 화면 포커스, 방향키 기본 동작, QWER 동시 입력, 탭 전환 시 입력 초기화.
- 일시정지·재시작과 스킬 대기시간.
- 일본어 폰트 누락, 창 크기에 따른 HUD 잘림.
- 적·총알·이펙트 개수와 프레임 저하. 대량 생성이 필요하면 오브젝트 풀링 도입.
- 첫 다운로드 용량, 로딩 표시, 호스팅 압축 설정.
- 개인 기록 저장 실패 처리. 온라인 공용 기록은 별도 API 단계에서 연결.
